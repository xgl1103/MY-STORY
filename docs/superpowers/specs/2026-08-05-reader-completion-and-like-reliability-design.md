# 阅读末页完成入口与评论点赞可靠性设计

## 背景

章节阅读器已经支持滑动和翻页两种阅读方式，并新增了评论点赞交互。当前还需要：

1. 在故事真正结束的位置提供“完成今日故事，返回首页”入口。
2. 修复代码复审发现的点赞持久化与失败回滚问题。
3. 用可执行行为测试覆盖关键交互，避免只依赖源码正则检查。

## 范围

### 末页完成入口

- 仅当当前章节没有下一章时显示。
- 作为阅读内容最后一个区块，位于评论汇总、命运选择或命运确认之后。
- 翻页模式下自然进入最后一页；滑动模式下位于文章底部。
- 按钮文字为“完成今日故事，返回首页”。
- 点击后仅导航到首页 `/`，不新增数据库完成状态，也不改变故事进度。
- 按钮必须是可访问的原生按钮，具有清晰焦点样式，并带 `data-no-page-turn`，确保点击不会被阅读器解释为前后翻页。
- 日间和夜间模式都使用现有主题变量，且不遮挡底部阅读进度条。

### 点赞持久化可靠性

- 数据库持久化调用必须串行排队；新的强制写入不能复用一个不包含最新内存状态的旧快照。
- `markWrite` 保留现有默认容错行为，但允许要求调用方感知持久化异常。
- `CommentRepository.setLiked` 在更新前读取原值；如果强制持久化失败，则恢复内存数据库中的原值并向上抛出错误。
- 点赞 SQL 继续保持原子、幂等、缺失记录返回 `null`，且点赞数不得小于零。
- 两个不同评论并发点赞后，重新加载持久化数据库时必须都保留最新状态。

### 点赞界面行为

- 点击后继续乐观更新、按评论 ID 加锁，并显示点赞或取消点赞动画。
- 保存成功后使用数据库返回值校准界面。
- 保存失败时立即恢复点赞数和点赞状态，同时立即清除该评论的动画与等待状态。
- 一个评论的动画、锁或失败不能影响其他评论。

## 结构

### `Database.js`

将持久化从“进行中时复用同一个 Promise”改为串行任务队列。每个入队任务在实际执行时导出数据库，从而包含排队前发生的最新写入。失败仍被记录；需要感知失败的调用方可以要求 `markWrite` 重新抛出。

### `CommentRepository.js`

`setLiked` 负责数据库状态变更与失败补偿：保存前取得原值，执行幂等更新，强制持久化；如果持久化失败，恢复原值并抛错，让界面进入回滚路径。

### 评论点赞控制器

把乐观更新、单评论锁、成功校准和失败回滚组织为一个可独立执行测试的小型控制器。Vue 页面负责把控制器状态映射到现有响应式数据和动画类，不引入新的 UI 框架依赖。

### `ChapterReader.vue`

页面使用控制器处理点赞，并在阅读内容末端渲染完成入口。入口仅由 `!hasNext` 控制，点击调用首页导航。

## 错误处理

- 持久化失败：恢复内存评论记录，界面恢复点击前状态，清除动画和锁，记录警告。
- 评论已不存在：仓储返回 `null`，界面按失败路径回滚。
- 重复快速点击同一评论：锁定期间忽略；不同评论可以独立处理。
- 首页导航失败不写任何数据，因此不会产生半完成状态。

## 测试

严格按 RED-GREEN-REFACTOR 实施：

1. 数据库测试覆盖失败传播、内存补偿、并发持久化、重载后状态以及真实的零下限场景。
2. 点赞控制器测试覆盖乐观更新、同 ID 防重、不同 ID 独立、成功校准、失败回滚及动画立即清除。
3. 阅读器契约测试覆盖末页按钮条件、首页路由和 `data-no-page-turn`。
4. 现有阅读模式测试确保交互按钮不会触发翻页。
5. 运行全量测试、生产构建和 Git 差异检查。

## 非目标

- 不增加“今日故事已完成”数据库字段。
- 不改变下一章导航、阅读进度计算或命运选择业务。
- 不增加悬浮按钮、弹窗确认或完成奖励动画。
- 不修改预览页面的末页行为。
