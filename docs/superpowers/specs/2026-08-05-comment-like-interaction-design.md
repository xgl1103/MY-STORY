# 评论卡片与持久化点赞交互设计

## 目标

让章节正文中的 AI 读者评论更紧凑、协调，并把静态爱心改造成可持久化的真实点赞交互。用户点赞或取消点赞后，红心状态与数字在刷新页面、重新进入应用后仍保持一致。

## 视觉布局

- 评论卡片宽度调整为父容器的约 `92%`，最大宽度 `680px`，水平居中。
- 保留现有头像、左侧主题色边线和卡片圆角，适当缩小横向内边距与内部留白。
- 点赞区域改为真正的按钮，扩大可点击范围但保持视觉轻量。
- 未点赞使用灰色空心/低强调爱心；已点赞使用红色实心爱心。
- 日间和夜间主题均继续使用现有 CSS 变量，不引入独立主题系统。

## 点赞交互

- 点赞按钮包含 `aria-pressed` 和随状态变化的无障碍标签。
- 点赞按钮属于交互控件，不得触发阅读器的左右区域翻页。
- 首次点击立即把当前评论标记为已点赞，数字加一。
- 再次点击立即取消点赞，数字减一且最低为零。
- 本地数据库写入期间锁定该评论的点赞按钮，避免快速连续点击造成重复计数。
- 数据库写入失败时回滚红心、数字和动画状态，并记录可诊断警告。

## 动画

- 点赞：爱心放大回弹、颜色过渡到红色，并显示一次轻微扩散/闪光；数字同步向上弹动。
- 取消：爱心短暂缩小后回弹为灰色；数字同步轻微向下回落。
- 动画通过短生命周期状态类驱动，动画结束后清理，保证每次点击都能重新播放。
- 在 `prefers-reduced-motion: reduce` 下关闭关键帧动画，仅保留颜色和数字的即时变化。

## 数据模型与迁移

- `chapter_comments` 新增 `is_liked INTEGER NOT NULL DEFAULT 0`。
- 初始建表 SQL 直接包含该字段。
- 新增数据库迁移版本 9，为既有数据库添加字段；历史评论默认未点赞，原有 `likes` 数字不变。
- `CommentRepository.setLiked(commentId, liked)` 负责原子更新：仅在状态真正变化时调整 `likes`，并保证数值不小于零。
- 更新完成后返回数据库中的 `likes` 和 `is_liked`，供界面校准乐观更新结果。
- 当前应用为单用户本地数据模型，不创建多用户点赞关联表。

## 页面数据流

1. `ChapterReader` 从数据库加载评论，同时获得 `likes` 与 `is_liked`。
2. 用户点击后，页面保存旧值并立即乐观更新当前评论对象与动画类。
3. 页面调用 `CommentRepository.setLiked` 持久化。
4. 成功时用仓储返回值校准界面；失败时恢复旧值。
5. 评论渲染数据变化继续触发现有分页重排逻辑，避免点赞数字宽度变化造成布局错误。

## 测试

- 数据库迁移测试：版本 8 升级到版本 9，字段存在、默认值为零、版本号更新。
- 仓储测试：点赞加一、重复设置不重复加一、取消减一、最低为零、状态持久化。
- 视图契约测试：点赞按钮、无障碍状态、交互处理、动画类与防翻页属性存在。
- 样式契约测试：卡片窄化居中、点赞与取消动画、减少动态效果适配存在。
- 运行阅读器专项测试、完整项目测试与生产构建。

## 非目标

- 不增加登录用户之间的独立点赞记录。
- 不增加网络同步或服务器端点赞 API。
- 不重新设计评论生成、渐进展示或评论排序逻辑。
- 不修改正文排版和阅读模式选择逻辑。
