# Planner 结构化输出修复测试记录

测试日期：2026-08-03

## 目标

验证 V2 编剧规划器能稳定生成可通过本地 Schema 校验的场景级剧情合同，避免系统无提示地退回确定性备用计划。

## 发现与修复

- 先前 7 天真实测试能完整通过，但 Planner 共调用 14 次，7 天均退回 `fallback`；根因包括 JSON 输出不稳定、1400 token 预算偏小，以及本地动作校验仅识别少量中文动词。
- 为 Planner 增加 JSON Object 模式、温度 `0` 和 2400 token 预算；该选项同时支持未来的 Vercel Serverless Function 转发。
- 明确要求 3–6 个完整场景、第一场景原样执行开场合同动作、结束合同必须包含可执行下一步。
- 动作校验改为拒绝“待定 / 推进剧情 / wait for more”等空泛占位语，而不依赖单一语言的动词白名单；最终正文仍由剧情合同审查器验证。
- Serverless 单 IP 10 分钟限额从 12 提升至 30，以容纳一次正常日更所需的多次受控 AI 调用，同时保留限流保护。
- 随后发现 MemoExtractor 仍会因非结构化响应退回 fallback；现已将日记解析、记忆提取、Critical 和日记因果审计统一接入 JSON Object 模式，避免“文本要求 JSON、模型却附带说明”造成的假失败。
- 旧内容质量门会因日记关键词未逐字出现而最多追加三次重写；现改为先进行语义审计，未通过则交给 V2 场景合同链路的一次因果修复，避免堆词和重复调用。

# 追加：Handoff 误伤修复与 Planner 命中率探针（2026-08-03）

## 背景

复盘最近几轮真实 7 天测试时发现，真正高频 fallback 的并不总是 Planner 本身：

- `real-7day-2026-08-03T02-20-47-292Z`：三天 `plan.source` 全部为 `ai`，但 Day 1 / Day 3 的
  Handoff `quality_status` 均为 `fallback`；
- `real-7day-2026-08-03T02-10-20-226Z`：Day 1~3 Handoff 全部 `fallback`；
- `real-7day-2026-08-03T02-39-58-337Z`：Day 2 的 Planner fallback 由该轮 20 秒请求上限超时导致
  （测试参数过紧，非产品逻辑回退，默认上限仍为 45 秒）。

即：上一轮修复已让 Planner 的 JSON 输出基本稳定，但 Handoff Cleaner 的本地文本规则存在误伤，
导致 AI 正常产出的交接单被降级，并让下一天 Planner 读到的是降级构造的交接单。

## 根因

1. `TRAILING_FRAGMENT` 正则把“以 了/着/的 结尾”的完整动作误判为截断残句。
   中文完整句如“林墨将铁门打开了”“林墨写下了完整的线索笔记”都会因此被清空，
   `unfinishedAction` / `immediateNextAction` 判无效 → 交接单 fallback。
2. `_isActionable` 长度门槛为 ≥8 字，把“林墨打开铁门”(7字)、“追查纹章来源”(6字)
   这类完全具体可执行的动作判为无效。
3. `activeGoal` 被误用动作校验（`requireAction: true`）。目标是“当天目的”而非动作，
   导致几乎所有交接单都背上“activeGoal 不是完整可执行动作”的 issue，质量被降为 cleaned。
4. 真实测试报告不保存 `validationErrors` / `qualityIssues` / `fallbackReason`，
   出现 fallback 后无法直接定位是哪一条本地校验拒绝。

## 修复

1. `TRAILING_FRAGMENT` 只保留“孤立标点 + 连接词收尾”（和/但/而且/所以/于是/因为/然后/接着/以及/或者/却/并）。
   不再把“了/着/的”结尾当残句；真正的截断由 Planner 的 P101 校验与场景合同审查继续兜底。
2. `_isActionable` 长度门槛降到 ≥5 字，并扩充 NON_ACTION 占位语（继续调查/继续追查/查明真相/了解更多等）。
3. 新增 `_isGoal`：`activeGoal` 只需 ≥4 字、非占位语，不再要求是动作。
4. 真实 7 天测试报告增强：
   - `plan.validationErrors`：保存 Planner 本地校验错误码与消息；
   - `handoff.{quality,source,fallbackReason,issues}`：保存交接单判定结论，
     不保留正文引用或原始交接内容（延续脱敏原则）。
5. 新增 `tests/planner-hit-rate-probe.mjs`：用真实 DeepSeek 对首日、含选择、含交接单、
   伏笔回收四类场景各跑 N 次，统计 `ai / ai_retry / fallback` 占比与校验错误分布。
6. `handoff-cleaner.test.mjs` 挂入 `npm test`，并新增回归用例：
   “了”结尾完整句、5~7 字短动作、目标非动作校验、连接词截断仍 fallback。
