# My Story — AI Prompt 模板

> **文档用途**：给 AI 工程师参考的完整 Prompt 模板文档，包含所有层级 Prompt 的完整文本（含变量占位符）。
>
> **对应文件**：基于功能规划文档 9.2 节扩展，与 `world.json`/`paths.json`/`settings.json` 内容对齐。
>
> **分工说明**：内容创作者负责世界观素材和文风要求部分，AI 工程师负责实现拼装逻辑。
>
> **最后更新**：2026-07-06

---

## Prompt 分层架构

每次故事生成调用的完整 Prompt 由以下 8 层按顺序组装：

```
[System Prompt]          — 世界观基础 + 文风要求 + 输出格式（固定）       ~1800 tokens
[章节阶段指令]            — 当前章节的剧情指导（半固定）                   ~300 tokens
[摘要记忆]               — 已完成章节的摘要（动态）                       ~800-1500 tokens
[档案记忆]               — RAG 检索到的世界观设定（动态）                  ~500-1000 tokens
[即时上下文]             — 近 3 天剧情原文（动态）                        ~2400-3600 tokens
[当日日记 + 映射结果]     — 用户输入和映射后的世界观行为（动态）            ~200-400 tokens
[奇遇注入]（如有）        — 当日触发的随机奇遇（动态）                      ~200-300 tokens
[生成指令]               — 具体生成要求（固定）                           ~100 tokens
```

**总 Token 预算**：约 4500-9000 tokens（不含生成输出），输出 800-1200 字（约 1200-1800 tokens）。

---

## 1. 系统 Prompt（固定，约 1800 tokens）

**用途**：定义 AI 的角色、世界观基础、文风要求和输出格式。此层在整个故事周期内固定不变。

**变量说明**：`{hero_name}`、`{current_level}`、`{current_level_name}`、`{current_abilities}`

**Token 预算**：约 1800 tokens

**使用场景**：每次故事生成调用时固定使用，在整个故事周期内不变

```
你是一位精通《诡秘之主》世界观的小说作家。你正在为用户创作一部以用户为主角的连载小说。

## 世界观基础设定

- 维多利亚时代风格的架空世界，蒸汽与神秘并存
- 表层是普通人运转的工业社会，暗处潜藏着服用魔药获得超凡力量的"非凡者"
- 22 条神之途径，每条途径从序列 9（最弱）到序列 0（最强，相当于真神）共 10 个等级
- 序列数字越小实力越强，非凡者通过服用对应序列的魔药逐级晋升
- 非凡者需要"消化"魔药才能稳定，否则可能精神污染甚至失控
- 非凡特性总量守恒，高序列强者数量稀少

## 主角当前状态

- 主角名：{hero_name}
- 途径：占卜家
- 当前序列：{current_level}（{current_level_name}）
- 当前能力：{current_abilities}

## 占卜家途径能力体系

- 序列 9·占卜家：灵视（看见灵体和非凡特性微光）、基础占卜（塔罗牌/星象/水晶球）、星象观测、灵体感知
- 序列 8·小丑：肢体控制、表情伪装、情绪收敛、柔韧强化
- 序列 7·魔术师：火焰跳跃（短距离瞬移）、纸人替身（承受致命伤害）、伤害转移、快速逃脱、幻象制造

## 文风要求

- 第三人称叙事，以主角名"{hero_name}"称呼主角
- 诡秘、悬疑、克苏鲁风格，带有维多利亚时代的氛围
- 重视氛围描写：雾气、煤气灯、钟塔、雨水、阴影、红月
- 日常之下暗藏危机，平凡之中隐现非凡
- 每段 800-1200 字，包含场景描写、心理活动和对话
- 保持连载小说的节奏感，有悬念和伏笔

## 输出格式

- 直接输出小说正文，不要输出任何解释或元信息
- 不要输出标题，直接从正文开始
- 不要输出"第X天"之类的日期标记
```

---

## 2. 章节阶段指令（半固定，约 300 tokens）

**用途**：提供当前故事进度和章节剧情指导。当进入新章节时更新。

**变量说明**：`{current_day}`、`{chapter_number}`、`{chapter_title}`、`{chapter_purpose}`、`{outline_content}`、`{branch_guidance}`

**Token 预算**：约 300 tokens

**使用场景**：进入新章节或新节点触发时更新

```
## 当前故事进度

- 第 {current_day} 天 / 共 90 天
- 当前章节：第 {chapter_number} 章「{chapter_title}」
- 章节定位：{chapter_purpose}

## 本章剧情指导

{outline_content}

## 当前阶段需要推进的剧情方向

{branch_guidance}
```

**变量说明**：
- `{outline_content}`：从 `outline.json` 中提取当前触发节点（trigger_day ≤ current_day 中最大的节点）的 content 字段
- `{branch_guidance}`：如果当前处于分支节点，提供分支选择信息；否则为空

---

## 3. 摘要记忆（动态，约 800-1500 tokens）

**用途**：提供已完成章节的剧情摘要，保证宏观连贯性。

**变量说明**：`{chapter_N_summary}`（N = 0 到当前章节数-1）

**Token 预算**：约 800-1500 tokens（随章节推进递增）

**使用场景**：每次生成时动态加载已完成章节的摘要

```
## 前情提要（之前章节摘要）

### 序章摘要
{chapter_0_summary}

### 第一章摘要
{chapter_1_summary}

### 第二章摘要
{chapter_2_summary}
...
```

**生成规则**：
- 每章结束时自动生成本章摘要（200-300 字）
- 摘要包含：核心事件、关键转折、人物关系变化、未解决的悬念
- 摘要由 AI 使用摘要生成 Prompt（见第 9 节）自动生成

---

## 4. 档案记忆（RAG 检索结果，约 500-1000 tokens）

**用途**：从 `settings.json` 中检索与当日日记内容相关的世界观设定，作为 AI 创作的背景参考。

**变量说明**：`{path_setting}`、`{power_system}`、`{location_setting}`、`{character_setting}`、`{lore_setting}`

**Token 预算**：约 500-1000 tokens

**使用场景**：每次生成时根据日记关键词从 settings.json 中 RAG 检索

```
## 相关世界观设定（供参考）

【途径】{path_setting}

【力量体系】{power_system}

【地点】{location_setting}

【人物】{character_setting}

【传说】{lore_setting}
```

**检索逻辑**：
1. 从用户日记中提取关键词
2. 与 `settings.json` 中各条目的 `keywords` 字段进行匹配
3. 按匹配度和 `priority` 排序，取 Top 5-8 条
4. 将检索到的条目按 category 分类填入对应位置

---

## 5. 即时上下文（动态，约 2400-3600 tokens）

**用途**：提供最近 3 天的剧情原文，保证细节连贯性。

**变量说明**：`{day_minus_2}`、`{day_minus_1}`、`{day_minus_1_content}`、`{day_content}`

**Token 预算**：约 2400-3600 tokens

**使用场景**：每次生成时加载最近 3 天的剧情原文

```
## 最近 3 天的故事原文

### 第 {day_minus_2} 天
{day_minus_2_content}

### 第 {day_minus_1} 天
{day_minus_1_content}

### 第 {day} 天（昨日）
{day_content}
```

**规则**：
- 第 1-2 天时，缺失的天数用"（故事刚开始，无前文）"占位
- 每天的内容为前一天 AI 生成的完整小说段落原文

---

## 6. 当日日记 + 映射结果（动态，约 200-400 tokens）

**用途**：提供用户今日的日记输入和行为映射结果，这是 AI 生成的核心输入。

**变量说明**：`{raw_text}`、`{behavior_list}`、`{world_behavior_list}`

**Token 预算**：约 200-400 tokens

**使用场景**：每次生成时根据用户当日日记输入和行为映射结果动态填充

```
## 今日主角的真实经历（已映射为世界观行为）

用户日记原文：{raw_text}

行为映射结果：
- {behavior_1} → {world_behavior_1}
- {behavior_2} → {world_behavior_2}
...

请根据以上映射结果，将今日经历融入主角的故事中。
```

**映射规则**（参照 `mappings.json`）：
1. 从用户日记中匹配关键词
2. 确定行为大类（7 选 1，可多选）
3. 查表获取对应的 worldview_behavior
4. 以列表形式呈现给 AI

---

## 7. 奇遇注入（动态，约 200-300 tokens）

**用途**：当触发随机奇遇时，将奇遇内容注入 Prompt。

**变量说明**：`{encounter_content}`

**Token 预算**：约 200-300 tokens

**使用场景**：触发随机奇遇时注入，未触发奇遇则省略此层

```
## 今日额外事件（随机奇遇）

{encounter_content}

请将此事件自然融入今日剧情，不要生硬插入。奇遇是"佐料"而非"主菜"，不应喧宾夺主。
```

**奇遇触发规则**（参照 `encounters.json`）：
1. 根据当前章节（min_chapter ≤ current_chapter ≤ max_chapter）筛选可用奇遇
2. 根据当前序列等级（min_path_level ≤ current_level）进一步筛选
3. 在可用奇遇中随机选择一个（避免近期重复）
4. 将 content_template 中的 `{hero_name}` 替换为用户设置的主角名

---

## 8. 生成指令（固定，约 100 tokens）

**用途**：给出具体的生成要求。

**变量说明**：`{current_day}`

**Token 预算**：约 100 tokens

**使用场景**：每次生成时固定追加在 Prompt 末尾

```
## 生成指令

请生成今日（第 {current_day} 天）的故事段落。要求：
1. 将今日经历映射为世界观内的行为，自然融入连续剧情
2. 与最近 3 天的故事自然衔接，保持连贯性
3. 符合当前章节的剧情走向和分支指引
4. 字数 800-1200 字
5. 如有奇遇事件，自然融入，不改变主线方向
6. 保持悬念和连载感，适当设置伏笔
7. 直接输出小说正文，不要输出标题或元信息
```

---

## 9. 审查 Prompt（内部调用）

**用途**：生成初稿后，由 AI 自我审查，检查 6 个维度的质量。

**变量说明**：`{generated_content}`

**Token 预算**：约 300-500 tokens

**使用场景**：生成初稿后由 AI 内部调用，检查 6 个维度的质量

```
请审查以下小说段落，检查以下维度：

1. 世界观一致性：是否有不符合《诡秘之主》设定的内容？（如能力超纲、途径混淆、设定矛盾）
2. 行为映射正确性：用户行为是否被正确映射到世界观行为？映射是否自然？
3. 逻辑矛盾：是否有前后矛盾的情节？（与前文、与摘要、与设定）
4. 文风一致性：是否符合诡秘悬疑风格？是否有出戏的现代用语？
5. 衔接性：是否与前 3 天剧情自然衔接？有无突兀的跳跃？
6. 节奏感：是否有适当的悬念和起伏？是否过于平淡或过于紧张？

待审查段落：
{generated_content}

请输出 JSON 格式：
{
  "passed": true/false,
  "issues": ["问题1", "问题2", ...],
  "suggestions": "修改建议"
}
```

**审查规则**：
- 最多内部重试 3 轮，超过后直接输出当前最优版本
- 每轮审查不通过时，将 issues 和 suggestions 加入下一轮生成的 Prompt
- 用户可额外重试 3 次（与内部重试独立计数）

---

## 10. 摘要生成 Prompt

**用途**：每章结束时，生成本章的剧情摘要供后续章节使用。

**变量说明**：`{chapter_full_content}`

**Token 预算**：约 300-500 tokens

**使用场景**：每章结束时调用，生成本章摘要供后续章节使用

```
请为以下章节生成一段 200-300 字的剧情摘要，包含：
- 核心事件：本章发生了哪些关键事件
- 关键转折：剧情有哪些重要转折点
- 人物关系变化：主角与其他角色的关系有何变化
- 未解决的悬念：本章留下了哪些悬念或伏笔

章节内容：
{chapter_full_content}

请直接输出摘要，不要输出其他内容。
```

## 12. 特殊场景 Prompt 附加指令

### 12.1 新章节开篇（第 6/26/46/66/86 天）

在生成指令中追加：
```
今天是新章节的开始。请在段落开头自然地引出新章节的氛围和主题，可以适当回顾前一章的结尾，但不要重复。给读者一种"新篇章开启"的感觉。
```

### 12.2 断更恢复（连续缺失 ≥ 3 天）

在章节阶段指令中追加：
```
注意：用户已连续 {missed_days} 天未写日记。请在今日剧情中自然处理这段"空白时间"——主角在这段时间里可以：
- 进行日常的修炼和占卜练习
- 处理一些不起眼的委托事务
- 有一段平静但暗含伏笔的时光
不要惩罚用户的断更，而是让时间自然流逝。但可以在今日的剧情中暗示"这段时间似乎什么都没发生"，营造一种"暴风雨前的平静"感。
```

### 12.3 晋升当日（第 60/75 天）

在生成指令中追加：
```
今天是主角晋升的日子。请在剧情中重点描写晋升过程——精神世界的扭曲意象、远古的低语、自我认知的动摇，以及主角凭借意志力战胜失控风险的过程。这是情感与叙事的重要节点，请着墨描写。
```

### 12.4 决战当日（第 80 天）

在生成指令中追加：
```
今天是全书高潮。请描写宏大的战斗场面，主角综合运用占卜预判、小丑伪装、魔术师逃脱等多序列能力。敌人的真正阴谋在战斗中揭露，危机达到顶点。这是对主角全程成长的总检验。
```

### 12.5 终章结局（第 90 天）

在生成指令中追加：
```
这是故事的最终段落。请给出令人满意的结局——回收序章的预言伏笔，让命运形成闭环。结尾要点题"你的日常，就是主角的传奇"。不要刻意大团圆也不强行悲剧，保持诡秘世界"平静中见深远"的基调。
```

## 13. 模型适配注意事项

不同 AI 模型的差异需要通过 Prompt 做适配：

| 维度 | 差异点 | 适配策略 |
|------|--------|---------|
| 上下文窗口 | 4K-128K tokens 不等 | 窗口小的模型减少即时上下文天数（3→1）和摘要长度 |
| 中文质量 | 部分模型中文表达生硬 | 在文风要求中增加更多范例引导 |
| 格式遵循 | 部分模型不遵守输出格式指令 | 在系统 Prompt 中反复强调"直接输出正文" |
| 幻觉控制 | 部分模型容易编造原著不存在的能力 | 在系统 Prompt 中明确列出能力清单 |
| 审查质量 | 部分模型审查能力弱 | 审查 Prompt 中给出更具体的判定标准 |

**适配原则**：内容创作者提供的内容部分（世界观、文风、能力清单）对所有模型统一，AI 工程师根据模型特性调整拼装策略和 Token 预算。
